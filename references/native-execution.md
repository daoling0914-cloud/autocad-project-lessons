# 原生执行与错误定位

## 选用当前环境已有的方式

先发现实际安装位置和可执行文件。不要沿用案例机器的盘符、AutoCAD 年份、COM ProgID、Python 路径或缓存目录。

| 方式 | 合适的任务 | 容易遗漏的条件 |
| --- | --- | --- |
| AutoCAD Core Console | 批量打开、保存、审计、执行已有 LISP/.NET 命令 | 本版支持的命令、插件目标版本、脚本输入及完成标记 |
| COM / ActiveX | 已有 COM 工作流、文字样式、打印配置及文档操作 | 实际注册的 ProgID、忙碌状态、枚举类型、实例归属 |
| AutoCAD .NET 插件 | 大量原生对象、布局视口、结构化回读和精确修改 | 使用实际安装版本 SDK 程序集；事务及文档/布局上下文 |
| ezdxf 等 DXF 工具 | 中间文件生成、几何计算、离线回读 | 不把其读取 DXF 当作原生打开最终 DWG 的替代 |

沿用已经适用的项目管线。只有确有能力缺口时才切换，不为了使用本 skill 安装另一套建模系统。

记录正在运行的 Python 可执行文件和其中可导入的模块。缺少 `ezdxf` 或 PDF 库时先核对解释器，不因另一解释器曾安装过就认为当前可用。用户要求后台处理时保留该约束；能发现软件路径并不证明许可证、启动或实际打印可用。

## 批处理完成条件

每次运行使用明确的输入文件、运行目录和输出文件。插件记录阶段性成功标记与错误信息；调用方同时检查进程退出状态、本轮完成标记及预期输出。完成标记、错误文件和中间 DXF 不跨轮次混用。

Core Console 日志在既有项目中出现 UTF-16LE；不要对任何安装环境强行套一种解码。优先识别 BOM，结合实际内容判断编码；保留原始日志，避免乱码把错误数变成不可读文本。

脚本被超时中断后先检查自己创建的进程和输出是否仍在变化，再决定继续等待或重试。按阶段耗时设置有限超时；终止时只处理本任务创建的实例及其子进程。不要按进程名批量结束其他 CAD 会话。

若日志显示 HKCU/profile 初始化失败，隔离 profile 只能分开配置，不能提升权限。先定位当前权限、许可和初始化条件；根因未变时不继续堆叠相同进程。专用用户数据缓存的复用需核对版本与并发占用，缓存不进入交付；盘点发现大缓存也不构成清理授权。

使用当前安装支持的国际化命令名/选项；如用 `_.AUDIT`，确认完整提示顺序，并从日志提取错误与修复数量。不要将插件单独打印的“成功”当作原生审计结论。若在输出副本上修复了错误，应保存并重新打开检查，不能把“修复若干项”写成“从未发现错误”。

## COM 忙碌与重试

只对已识别的暂时忙碌/调用被拒绝状态进行有期限重试。参数错误、缺文件、字体不存在和保存格式不支持应直接定位。不要复制“所有异常都吞掉，再重试几十次”的历史脚本写法；对象创建、复制和保存中途失败后，先核对是否已发生副作用，避免重复实体和重复文件。

需要独立实例时记录该实例的所有权；需要操作用户现有文档时精确选择目标文档。只关闭自己创建的文档/实例。COM 属性写入失败可核对本版类型库与 `PROPERTYPUT` 调用方式，不先假定权限不足。

## `eNotInPaperspace`

已观察到的失败点是设置 `Viewport.On`。这是上下文错误的诊断入口，不是增加延时即可修复的证据。

检查 `TILEMODE`、`LayoutManager.CurrentLayout`、视口是否属于目标布局的纸空间块记录，以及对象是否已经正确加入数据库/事务。在纸空间布局中创建并启用目标视口后，回读其所属布局、中心、宽高和比例，并实际打印该布局。不要删除编号为 1 的系统视口。

这些是排查项，不保证修改某一个变量就解决所有同名异常。现有日志只证明出现过这个故障；应以本轮成功回读和打印作为修复证据。

## 数据库资源与空白布局页

从其他数据库借用图层、线型或样式的 ObjectId 前，确认该资源在目标数据库中有效，必要时在目标库加载或克隆资源。师兄包记录过无效线型引用引起的 `eNullObjectId`；本轮须结合对象及原生日志确认，不能把同名错误都归因于线型。需要临时切换 `HostApplicationServices.WorkingDatabase` 时，保存原值并在异常路径也恢复。

PDF 只有图框时，除了纸空间上下文，还应区分系统总体视口与显示模型的浮动视口，并检查视口启用状态、目标、中心、高度、比例、图层和可见性。师兄包报告过唯一视口被作为总体视口而未显示模型的案例；不要仅凭侧数据库读到的 `Viewport.Number` 判定创建成功。以原生打开和最终页面确实包含模型为准。

用户打开 CAD 要看到的模型/布局空间与 PDF 打印布局可分别有要求，保存前核对两者。若 Zoom Extents 后主体异常缩小，先查离群远点、大圆或异常范围；不要直接缩放主体来掩盖问题。仅处理本次确认属于误留的对象。

## 选择器返回空集合或意外数量

项目曾因图框定位筛选后直接 `.First()` 报“序列不包含任何元素”；另一处因白色对象数量硬编码报错。遇到这类失败，应输出候选对象的类型、图层、范围与变换，确认是否选错对象或选错版本。不能改成取任意对象，也不能把旧案例数量直接调成当前数量来通过检查。

先只读收集候选并验证，再在事务内修改；前置条件失败时不提交修改。任务结束后校验本次目标是否达成以及周边对象是否保留。
