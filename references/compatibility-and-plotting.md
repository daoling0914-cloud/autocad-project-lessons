# 兼容、字体与最终打印

## 保存版本要检查实际文件

使用本版 AutoCAD 的符号枚举或命令选择保存类型，不依赖历史脚本中的裸整数。文件名带“2004”或“2010”不能证明格式正确。

| 要求的格式系列 | 既有交付使用的六字节文件头 |
| --- | --- |
| AutoCAD 2004–2006 | `AC1018` |
| AutoCAD 2010–2012 | `AC1024` |

文件头只用于格式初筛。旧版保存后重新打开最终 DWG，回读文字、对象类型、尺寸和必要的外部依赖，并执行原生审计。检查最终文件，不检查中间高版本文件。`SaveAs` 会改变活动文档的文件身份；连续保存多份时明确当前正在打印和修改的是哪一份。[Autodesk SaveAs 文档](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-ActiveX-Reference/files/GUID-ED0D0B02-25FC-4ED2-9DEE-2B0C9AA9416A.htm)

## 中文与符号必须走完回读

逐项确认目标机器实际可用的文字样式字体、TTF 字体面名称或 SHX/BigFont 配对。MTEXT 内嵌字体覆盖可能绕过全局样式修改。不能因当前机器预览正常就认为收件人也有相同字体。

字体排查包括块内对象、ATTRIB/ATTDEF、MTEXT 内联字体和引线文字；样式表已替换不代表依赖已清理。若问题还涉及外参或代理对象，应先确认其来源及显示方式，不能一律改字体。某字体在旧案例修好了缺字，也不成为所有新图的默认替换字体。

项目旧版转换曾出现一段 MTEXT 内容在回读后发生变化。按原始文字记录定位修复后，再保存和回读验证。对适用的旧编码 DXF/文字路径，可测试保留 `\U+XXXX` Unicode 转义；不能将它无条件施加到所有文本、MTEXT 控制符或非 BMP 字符。

逐项比较文字语义与关键符号，并看实际打印：中文、直径、度数、正负号、公差框格、上下标。PDF 文本提取不保证识别 SHX 或轮廓字；提取不到时结合 CAD 文字对象和视觉判断，不能直接结论为文字丢失。

保持用户需要编辑的文字仍为文字。若确实需要文字轮廓以保证展示一致，说明取舍并保留可编辑来源，不能悄悄把所有文字转成几何。公开包也不随意附带商业字体文件。

## 打印设备与纸张

先选择实际可用的 PC3 设备，刷新设备/纸张列表，再从返回列表选择正确纸张。不要猜本地化显示名或写死旧机器的 canonical media 名称；不可用时报告实际候选，不无声换纸张。[Autodesk RefreshLists 文档](https://help.autodesk.com/cloudhelp/2026/ENU/OARX-ManagedRefGuide/files/OARX-ManagedRefGuide-Autodesk_AutoCAD_DatabaseServices_PlotSettingsValidator_RefreshLists_PlotSettings.html)

设置正确的纸空间布局或模型空间打印窗口；检查纸张单位、方向、原点、可打印边界、图框、标题栏和非打印视口图层。布局采用纸面毫米时通常按 1:1 出图，模型显示比例由视口控制；模型空间直接打印则要明确窗口和自定义比例。

要求改图层颜色时，还要检查实体 TrueColor、块内覆盖及 ByLayer/ByBlock 继承；图层表变色不保证实体或打印随之改变。按交付需要查看屏幕背景与白纸输出，避免只在一种背景下成立。

## 单位与比例

核对实际几何单位，不能只读单位标志。`INSUNITS` 影响插入时的缩放；修改它不会把现有坐标自动变成另一种单位。常见值为毫米 4、米 6。[Autodesk INSUNITS 文档](https://help.autodesk.com/cloudhelp/2026/ENU/AutoCAD-LT/files/GUID-A58A87BB-482B-4042-A00A-EEF55A2B4FD8.htm)

纸面毫米、标称比例 1:N、每模型单位代表 U 毫米时，视口纸面/模型比例为 `U / N`。例如毫米模型 U=1，米模型 U=1000。用一条已知长度从最终 PDF 独立量取纸面长度验证，避免模型和打印两次缩放。要求准确比例时不能改用“布满图纸”。

PDF 的页面尺寸与内容比例是两项检查；正确的 A3 页面不能证明内容为 1:1。合并 PDF 后也需检查页数、方向和图序。

## 线宽与最终视觉

核对对象及图层线宽、ByLayer 继承、CTB/STB、PlotWithLineweights/PrintLineweights 和打印样式开关。屏幕上的 `LWDISPLAY` 不能代表 PDF 实际线宽。

某项目要求 0.50/0.25 mm，而驱动输出出现约 0.508/0.254 mm。仅在明确要求精确数值且原生设置无法满足时，才考虑针对该驱动输出的后处理；必须处理变换矩阵并验证几何、文字、页面和比例未变。不要把重写 PDF 内容流当成所有出图任务的默认步骤。

实际渲染最终 PDF，并放大修订区、细密尺寸、公差、粗细交界和标题栏。文件审计、线宽数字或矢量路径数量均不能替代这一步。没有图像查看工具时保留可检查的渲染文件，并准确报告视觉核验尚未完成。

旋转尺寸可能被文本提取器拆成多段或改变顺序；先核原生文字边界及页面渲染，再判定漏字。PDF 页面旋转和 UserUnit 也需纳入纸张尺寸计算。任务本来要求空白模板时，不能以“没有正文文字”判定导出失败。

## 打包

先完成本轮 DWG 和 PDF，再打包。校验 ZIP 完整性和每个交付成员的字节/哈希是否与当前最终文件一致；不要只检查同名文件存在。交付文件夹清楚标注修订，避免多个“final”混放。

`scripts/check_delivery.py` 可自动完成其中的文件头、页数、纸张、ZIP 和哈希检查；几何、内容比例、原生回读及视觉核验仍由当前任务完成。

验收记录同时保存当前文件 SHA256、工具/版本、检查范围、结果与必要日志。文件发生实质变更后，旧摘要对应的通过记录不能自动沿用到新文件。即使外部报告声明通过且摘要匹配，也只说明记录绑定了该文件，仍需了解记录来源及实际检查内容。
